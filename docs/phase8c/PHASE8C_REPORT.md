## Security objective

A coordinate may be accepted or returned only through an App-Check-protected callable path whose server-side authorization is derived from current authoritative state. Direct Firestore coordinate reads and writes remain denied to clients.

## Implemented protocol

### Share-session issuance

- Session IDs are generated by Firestore on the server; the client cannot choose them.
- Starting a session requires `VISIBLE_APPROVED` or `VISIBLE_SELECTED` mode.
- Each new session advances `privacyEpoch` and binds that epoch to the session.
- A prior active session is deactivated when a new one starts.
- Starting a new session deletes any retained coordinate from the prior session.
- Session lifetime is currently 30 minutes.

### Coordinate publication

`publishLiveLocation` requires:

- Firebase Authentication.
- `identity_verified == true`.
- non-anonymous identity.
- Firebase App Check.
- limited-use/replay-protected callable token.
- caller identity is the location owner; owner ID is not accepted from the request body.
- exact active session ID match.
- exact `privacyEpoch` match.
- active, unexpired session.
- latitude in `[-90, 90]`.
- longitude in `[-180, 180]`.
- finite accuracy between `0` and `10,000 m`.
- capture no older than 120 seconds.
- capture no more than 30 seconds in the future.
- minimum 5-second publication interval.

The publication throttle is persisted on the server-only share-session record, so owner emergency deletion of the live-location document cannot reset the throttle.

### Viewer read

`getLiveLocation` returns a coordinate only when all of the following remain true at read time:

- viewer is authenticated, verified, non-anonymous and App-Check validated.
- owner live sharing remains enabled.
- visibility is `VISIBLE_APPROVED` or `VISIBLE_SELECTED`.
- current active session ID matches the session and location.
- current `privacyEpoch` matches the session and location.
- session is active and unexpired.
- relationship is `AUTHORIZED`.
- owner and viewer consent are both active.
- consent is not expired.
- selected mode includes the viewer explicitly.
- stored coordinate remains fresh and structurally valid.

Denied, hidden, stale, revoked, blocked, missing or malformed states return only:

```json
{"available": false}
```

No denial reason, prior coordinate, distance, timestamp or approximate position is returned.

## Hidden / revoke / block behavior

Privacy invalidation:

1. disables live sharing;
2. clears `activeShareSessionId`;
3. advances `privacyEpoch`;
4. marks the prior share session inactive; and
5. deletes the retained `liveLocations/{owner}` document.

An upload carrying the old session or epoch is rejected after invalidation commits.

## Firestore client boundary

Clients cannot directly read, create or update `liveLocations` documents, including the owner and an authorized viewer. Firebase Admin callables are the only remote coordinate read/write path.

The owner retains direct emergency delete permission because deletion reduces retained sensitive data and cannot expose a location.

Privacy, consent and share-session writes remain server-authoritative.
